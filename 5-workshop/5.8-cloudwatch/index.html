Configure Amazon CloudWatch Logs

Monitor EC2 Application Logs with Amazon CloudWatch

Overview

Amazon CloudWatch is used to collect, store, and review operational data generated by AWS resources and applications. In this implementation, CloudWatch Logs was configured to centralize the logs of the CenFra-MS application running on an Amazon EC2 instance.

The implementation included the following main tasks:

  • Creating an IAM role for Amazon EC2.
  • Attaching the CloudWatchAgentServerPolicy managed policy.
  • Assigning the IAM role to the EC2 instance.
  • Creating a CloudWatch log group and log stream.
  • Verifying that the application logs were successfully delivered to CloudWatch Logs.

The configuration flow is shown below:

CenFra-MS application on EC2
            |
            v
IAM role with CloudWatchAgentServerPolicy
            |
            v
CloudWatch Log Group: ec2-c8n-clW
            |
            v
Log Stream: cenfra-app
            |
            v
Application log events

The EC2 instance and CloudWatch resources in this implementation were configured in the US West (Oregon) Region (us-west-2). IAM is a global AWS service, while EC2 and CloudWatch resources are Region-specific.

1. Create an IAM role for Amazon EC2

Open the AWS Management Console and navigate to:

IAM → Roles → Create role

In Trusted entity type, select AWS service. Under Service or use case, select EC2, and then choose the EC2 use case.

This trust relationship allows the EC2 service to assume the IAM role and use the permissions attached to it.

Figure 1: Selecting Amazon EC2 as the trusted entity for the IAM role.

Choose Next to continue to the permissions configuration.

2. Attach CloudWatch permissions

On the Add permissions page, select Use existing policy and search for:

CloudWatchAgentServerPolicy

Select the AWS-managed policy named CloudWatchAgentServerPolicy.

Figure 2: Attaching the CloudWatchAgentServerPolicy managed policy.

This policy provides the permissions required for the CloudWatch agent running on the EC2 instance to publish monitoring data and application logs to Amazon CloudWatch.

Choose Next after selecting the policy.

3. Review and create the IAM role

On the final page, review the trusted entity and permission policy.

The trust policy identifies Amazon EC2 as the principal that can assume the role:

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "sts:AssumeRole",
      "Principal": {
        "Service": "ec2.amazonaws.com"
      }
    }
  ]
}

Confirm that CloudWatchAgentServerPolicy appears in the permission policy summary.

Figure 3: Reviewing the EC2 trust policy and CloudWatch permission policy.

The IAM role used in this implementation was named:

ec2-cloudWatch

Choose Create role to complete the IAM role configuration.

4. Attach the IAM role to the EC2 instance

Navigate to:

EC2 → Instances

Select the EC2 instance that runs the application. In this implementation, the instance name was CenFra-MS.

From the instance menu, choose:

Actions → Security → Modify IAM role

Figure 4: Opening the Modify IAM role option from the EC2 instance page.

On the Modify IAM role page, select the previously created role:

ec2-cloudWatch

Figure 5: Selecting the ec2-cloudWatch role for the CenFra-MS instance.

Choose Update IAM role.

After the update, applications or monitoring agents running on the instance can obtain temporary credentials through the EC2 instance profile. Therefore, long-term AWS access keys do not need to be stored directly on the server.

5. Create a CloudWatch log group

Open Amazon CloudWatch and navigate to:

CloudWatch → Logs → Log management → Create log group

Configure the log group with the following values:

SettingValue
Log group nameec2-c8n-clW
Retention setting1 day
Log classStandard
KMS keyNot configured
Deletion protectionDisabled

Figure 6: Creating the ec2-c8n-clW CloudWatch log group.

The one-day retention period was selected for the demonstration environment to prevent test logs from being stored longer than necessary. For a production environment, the retention period should be selected according to operational, compliance, and cost requirements.

Choose Create to create the log group.

6. Create a log stream

Open the newly created log group and select Create log stream.

Enter the following log stream name:

cenfra-app

Figure 7: Creating the cenfra-app log stream.

A log group is a container for logs belonging to the same application or workload. A log stream represents a sequence of log events from a specific source, such as an EC2 instance, container, application process, or log file.

Choose Create to complete the log stream configuration.

7. Verify the log group and log stream

Return to the ec2-c8n-clW log group.

The Log streams section should display the newly created stream:

cenfra-app

Figure 8: Verifying that the cenfra-app log stream is available.

The presence of a recent value in the Last event time column indicates that CloudWatch has received log events for the stream.

8. Review application log events

Open the cenfra-app log stream to inspect the collected events.

The log stream contains startup and runtime information from the Spring Boot application, including:

  • Spring Boot application initialization.
  • Embedded Tomcat startup on port 8080.
  • Spring Data JPA repository initialization.
  • HikariCP database connection pool startup.
  • PostgreSQL JDBC driver and database information.
  • Hibernate initialization.
  • Spring Security configuration.
  • Application endpoint initialization.

Figure 9: Spring Boot startup events delivered to CloudWatch Logs.

Additional events confirm that the application connected to PostgreSQL and completed its initialization process.

Figure 10: Database, Hibernate, Tomcat, and application events in CloudWatch Logs.

The log event page can also be used to:

  • Search for keywords such as ERROR, WARN, or an exception name.
  • Filter events by a custom time range.
  • Tail new events in near real time.
  • Open the log group in CloudWatch Logs Insights for advanced queries.
  • Create metric filters from matching log patterns.

Result

Amazon CloudWatch Logs was successfully configured for the CenFra-MS EC2 workload.

The completed setup provides the following results:

  1. The EC2 instance has an IAM role with permission to publish monitoring data.
  2. The IAM role is attached to the CenFra-MS instance.
  3. The ec2-c8n-clW CloudWatch log group stores the application logs.
  4. The cenfra-app log stream receives events from the application.
  5. Spring Boot, Tomcat, Hibernate, and PostgreSQL-related events can be reviewed from the AWS Management Console.

Centralizing logs in CloudWatch makes it easier to troubleshoot application issues without repeatedly connecting directly to the EC2 instance. The collected events can later be used with Logs Insights, metric filters, dashboards, alarms, and notification services to build a more complete monitoring solution.

Notes for production deployment

For a production environment, consider the following improvements:

  • Apply the principle of least privilege instead of granting unnecessary permissions.
  • Configure a retention period appropriate for the organization’s requirements.
  • Use AWS KMS encryption when additional control over log encryption is required.
  • Add CloudWatch metric filters for important patterns such as ERROR and failed authentication attempts.
  • Create CloudWatch alarms and Amazon SNS notifications for critical conditions.
  • Avoid writing passwords, tokens, connection strings, or other sensitive information to application logs.
